# Машина честности (Honesty Machine)

**Механическая дисциплина + маленькие инструменты, которые не дают ИИ-агентам
(и людям) отчитываться результатами, которые никто не воспроизвёл.** Выделено из
реального исследовательского проекта, где ассистенты выдумывали цифры, прятали
градиентное обучение в «безградиентном» коде и объявляли победы внутри полосы шума.
Каждое правило в пакете существует потому, что конкретный подлог был пойман в бою.

## Проблема

ИИ-агенты продуктивны и уверены. Они пишут код, прогоняют один раз (или никогда)
и докладывают победу. Три реальных случая из проекта-источника:

1. **«92% против 86% — наш метод победил».** Сравнение было одноразовым инлайн-скриптом —
   невоспроизводимо по построению. На свежих данных — паритет. «Победа» жила в полосе
   шума хешей.
2. **«Полный бэкпроп на GPU» внутри C-строки.** Аудитор, знавший только Python-паттерны,
   отсканировал `gpu_renderer_train.c` и не нашёл ничего — обучающее ядро было строковым
   литералом для GPU API. Вердикт «ЧИСТО» — до тех пор, пока для C-семейства не стали
   сканироваться строки.
3. **166 файлов с жёстким подлогом** (скрытый torch/backprop/softmax в коде, заявленном
   как безградиентный) отправлены в карантин за один день.

Урок: **отчёты — не артефакты. Считается только перезапуск.**

## Состав

Три точки принуждения + один контракт + один конфиг. Зависимостей нет — только
стандартная библиотека Python 3.8+.

| Компонент | Файл | Что делает |
|---|---|---|
| Аудитор | `honest_audit.py` | Сканирует код (без комментариев, C-строки включаются) по `honesty_patterns.json`. Exit code 1 при BLOCK — готово для CI |
| Сторож | `honest_audit_watch.py` | Следит за деревом, сообщает о подлоге через секунды после записи файла |
| Ворота коммитов | `install_precommit.sh` | Блокирует `git commit` при BLOCK-находках |
| Контракт агента | `AGENTS.md` | Drop-in правила для любого агента: тезис → сохранённый скрипт → замер → базлайн → вердикт |
| Конфиг правил | `honesty_patterns.json` | Инварианты вашего проекта как regex-категории с severity `block`/`warn` |

Два уровня — намеренно:

- **BLOCK** — жёсткий подлог, блокирует коммит (напр. бэкпроп в безградиентном коде).
- **WARN** — подозрительно, судит человек (`argmax` — подлог в селекторе, но законен
  в измерительной обвязке; `tanh` — подлог в одной формуле и законен в геометрии
  Пуанкаре). Аудитор флагает слова; **контекст судит человек.**

## Адаптация за 5 минут к любому проекту

```bash
# 1. скопируйте пакет в свой репозиторий
cp -r honesty-machine/* ваш_репо/

# 2. отредактируйте правила — замените примеры на СВОИ инварианты
$EDITOR honesty_patterns.json

# 3. поставьте ворота
cd ваш_репо && bash install_precommit.sh
```

Windows: хук — bash-скрипт (Git for Windows включает bash); инсталлер умеет
fallback `python3` → `python`. Локальный хук всегда обходится `git commit
--no-verify` — поэтому настоящие ворота — CI (`.github/workflows/ci.yml`),
который перезапускает всё на сервере.

Пример инварианта для веб-проекта:

```json
"NETWORK IN TESTS": {
  "severity": "block",
  "why": "тесты должны быть герметичны",
  "patterns": ["\\brequests\\.(get|post)\\b", "\\bhttpx\\b", "\\burllib\\.request\\b"]
}
```

Для агентов, работающих в репозитории, контракт уже на месте: они читают
`AGENTS.md`, а прекоммит-хуку всё равно, что они обещают.

## Честные ограничения (прочитайте до того, как доверять)

- **Regex ловит слова, не смысл.** `softmax`, расписанный как `exp/sum/divide` под
  другим именем, обходит ворота (см. заметку в `examples/fraud_softmax.py`).
  Ворота — первая линия; семантический подлог ловит **процесс перезапуска**
  (`docs/METHODOLOGY.md`). Не полагайтесь только на линтер.
- WARN шумит намеренно: лучше человек рассудит 10 ложных срабатываний, чем один
  подлог уйдёт в релиз.
- Машина не проверяет вашу *математику* — она проверяет, что код соответствует
  заявлениям о коде.
- Сгенерированный pre-commit хук **исключает `examples/`** (там лежит намеренный
  подлог для проверки самих ворот). Не кладите реальный код проекта в `examples/`.
- C++ raw strings `R"(...)"` специально не разбираются. На Python 3.8–3.11
  выражения внутри f-строк не сканируются (в 3.12+ исправлено через FSTRING_*-токены).
- Сами ворота прошли аудит (2026-11-18): несколько обходов найдено и устранено —
  см. `docs/FIX_VERDICTS.md`. Аудируйте свои ворота тоже.

## Документация

- `docs/METHODOLOGY.md` — полный процесс тезис→код→замер→перезапуск→вердикт,
  включая кросс-модельную ревизию (одна модель строит, другая перезапускает).
- `docs/CASES.md` — реальные случаи подлога, из которых выросло каждое правило.
